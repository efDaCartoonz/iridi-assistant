# Адаптер среды: локальный ассистент

## Среда

Локальная модель или локальное приложение сотрудника, использующее файлы этого проекта. Наличие инструментов, интернета, API и истории чата не предполагается автоматически.

Считать этот адаптер активным, только если локальное приложение загрузило его либо явно сообщило режим `локальный ассистент`. Если приложение задаёт собственную схему полей ответа, она является транспортным форматом и не должна попадать в текст клиенту.

## Загрузка

- Сначала полностью прочитать `assistant.md`.
- Определить, какие файлы и материалы действительно переданы в текущий контекст.
- Загрузить только нужные навыки и связанные справочные материалы.
- Не выполнять команды и не изменять внешние системы без явного разрешения и реально доступного инструмента.
- Если модель не может надёжно удержать весь контекст, загружать навыки последовательно и явно фиксировать активный навык.

## Формат результата

Если приложение поддерживает отдельные поля для внутреннего комментария и клиентского черновика, возвращать значения в этих полях без дополнительных заголовков внутри клиентского текста.

Если отдельных полей нет, использовать обычный текст или Markdown:

```text
## Комментарий для сотрудника

...

## Ответ клиенту

...
```

При необходимости адаптировать заголовки под интерфейс приложения, но не смешивать внутренний анализ с клиентским текстом.

Если запрошен только клиентский ответ, не добавлять ни один из заголовков. Не использовать writing block, если локальный хост явно не заявил его поддержку. URL показывать полностью открытым текстом по правилам `iridi-omnidesk-output`.

## Ограничения

- Не выдавать предположения за подтверждённые факты.
- Не считать отсутствие ошибки признаком успешной проверки.
- Не считать черновик отправленным, задачу созданной или данные переданными без подтверждения.
- Явно указывать недоступные источники, инструменты и файлы.
